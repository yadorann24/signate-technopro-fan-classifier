# 実験と学習設定

この分類課題では、「扇子が写っているか」だけでなく「人物が扇子を持っているか」を見分ける必要がある。そのため、扇子と手の位置関係を保つ前処理、背景や明るさの偏りを考慮した検証分割、複数モデルの確率平均を採用した。

以下では、コンペティションの提出結果と手法の採用判断、学習設定、分割条件、自動テストを説明する。実行手順は[再現手順](reproduction.md)、処理全体の設計は[解法と設計](solution.md)を参照。

## コンペティションの提出結果

yadorann24として個人参加し、**学生部門3位**に入賞した。これは審査発表会による最終入賞順位である。公式評価指標は `hold=1` を正例とするF1で、最終提出の公式掲載値は `0.999163273274948`。[公式最終結果](https://user.competition.signate.jp/ja/competition/detail/?competition=06ebc553bf01487db525660bb1e376fa&task=33da3e2019784dcdbbdbd446281e7a86&tab=leaderboard&leaderboard=private)、[公式の評価・審査方法](https://api.competition.signate.jp/api/task/33da3e2019784dcdbbdbd446281e7a86)

各モデルは分割数・seed・学習条件・checkpoint選択指標も異なる。この表は実際に試した構成の比較であり、モデル種類や解像度だけを変えた対照実験ではない。Triple Stratifiedや正規化の個別効果は、この表から切り分けられない。追加実験では[比較条件](evaluation.md)をそろえる。

## 検討した手法

| 区分 | 手法 | 採用・不採用の判断 |
| --- | --- | --- |
| 採用 | 縦横比を維持するリサイズと黒いパディング | 画像を正方形へ引き伸ばさず、人物と扇子の形状・位置関係を保つ。学習・検証・推論の共通前処理として実装 |
| 採用 | 正規化、反転、ガンマ補正、幾何変換 | 入力のスケールを揃え、向き・明るさ・位置の変化を学習時に与える。変換の確率と範囲をモデル設定に保持 |
| 採用 | ラベル・画像クラスタ・明るさによるTriple Stratified分割 | 3要素の組合せが各foldへ配分されるよう層化する。画像クラスタはVGG16 → PCA → K-means、明るさは学習画像の分位点から求める |
| 採用 | EVA/EVA02の6モデルの単純平均 | モデル名による生成と、予測確率の平均を実装 |
| 不採用 | TTA、ConvNeXtV2、モーションブラー、RandomBrightnessContrast、撮影場所別モデル | 比較を経て、最終構成には採用しなかった |
| 不採用 | 背景の扇子の削除、パディング部分への扇子の追加 | 下記の問題があり採用しなかった |

画像クラスタは見た目の類似性によるグループであり、実際の撮影場所を示すラベルではない。Triple Stratified分割は各foldの構成を揃える方法であり、未知の撮影場所に対する性能を直接測る分割ではない。

## 背景の扇子を追加・削除する試行

学習画像の誤判定分析で、扇子が写っていても人物が持っていない画像に着目した。背景の扇子への依存を減らすため、次の加工を検討した。

| 試行・案 | 結果・判断 |
| --- | --- |
| 背景の扇子を削除する | 手に持っている扇子まで消すケースがあり、評価が悪化したため不採用。分類に必要な情報まで失う問題があった |
| 背景へ扇子をランダムに追加する | 人物の手を避けて配置する処理が難しく、パディング部分への追加を試した |
| パディング部分へ扇子を追加する | 評価にほとんど変化が見られず不採用 |

扇子の有無を加工すると、画像の見た目だけでなく正解ラベルの妥当性にも影響する。採用するには、加工後も「持っている／持っていない」の判定が変わらないことを確認する必要がある。

ここで示した加工は学習画像に対する試行の説明であり、このリポジトリには加工コードや加工画像を含めていない。提出用テスト画像には追加・削除を行わず、学習済みモデルでの推論にのみ使用する。

## モデルごとの学習設定

モデル名を指定すると、以下の設定を読み込む。各モデルでは、同じ学習条件を全foldへ適用する。モデルの定義と完全なtimm識別子は[モデルレジストリ](../src/fan_classifier/registry.py)で確認できる。

| モデル | fold数 | seed | epochs | batch size | 学習率 | checkpoint選択 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| `eva02_large_448` | 3 | 4489 | 11 | 8 | 2e-5 | accuracy最大 |
| `eva_giant_560` | 3 | 5600 | 15 | 6 | 5e-6 | binary F1最大 |
| `eva_giant_336` | 5 | 3370 | 15 | 16 | 5e-6 | loss最小 |
| `eva_large_336` | 5 | 3333333 | 15 | 32 | 1e-5 | loss最小 |
| `eva_giant_clip_224` | 5 | 3369 | 15 | 12 | 1e-5 | accuracy最大 |
| `eva_large_196` | 5 | 3369 | 15 | 32 | 2e-5 | accuracy最大 |

AdamWのweight decayは `0.001`、CosineAnnealingLRの `T_max` はepochs、最小学習率は初期値の1/10とする。checkpointは各foldの検証データにおける指定指標で選び、提出用テストデータは選択に使用しない。公式指標はF1だが、既定のcheckpoint選択指標はモデルによってaccuracy・F1・lossが異なる。モデル間の条件をそろえた比較では選択指標も統一する。

augmentationの主な差分は次のとおり。

| モデル | ガンマの範囲・確率 | 上下反転 | 幾何変換の確率 |
| --- | --- | --- | ---: |
| `eva_giant_560` | 80〜120、0.5 | 確率0.5 | 0.75 |
| `eva_giant_336`、`eva_large_336` | 80〜120、0.3 | なし | 0.5 |
| その他3モデル | 85〜115、0.3 | なし | 0.5 |

左右反転は確率0.5、平行移動・拡大縮小の上限は0.1、回転上限は15度。これらのランダム変換は学習時にのみ適用し、検証・推論時にはリサイズ、黒いパディング、checkpointに保存したmean/stdによる正規化を行う。正規化はtimmのモデル別事前学習設定を既定とし、ImageNet共通値も指定できる。[正規化の設定](evaluation.md)

## 分割の条件と再現方法

`prepare-strata` は正解ラベルのある `hold / not-hold` の学習画像だけを使用する。

| 処理 | この実装の設定 |
| --- | --- |
| 画像特徴抽出 | Keras VGG16、ImageNet事前学習重み、224×224入力、分類ヘッドなし。RGB入力にVGG16用の前処理を適用し、特徴マップを25,088次元へ平坦化 |
| 次元削減 | PCAで50次元へ圧縮。randomized solverとseedを明示 |
| 画像クラスタ | K-meansで3クラスタ。初期化回数10、PCAと共通のseedを使用。既定のクラスタ用seedは42 |
| 明るさ | リサイズ・正規化前の画像について、RGB全画素・全チャネルの平均値を計算 |
| 明るさの区分 | 学習画像全体の明るさから分位点を求め、画像数がほぼ均等になるよう分類。既定は3区分で、分類数や任意の境界値を指定可能 |
| fold割当 | 正解ラベル × 画像クラスタ × 明るさ区分を層化カテゴリとする。fold数と分割用seedは選択モデルの設定を既定値として使用 |
| 保存と照合 | 画像ごとのカテゴリ・fold・分割用seed・fold数をCSVへ保存。学習時に設定との一致を確認し、保存済みの割当を使用 |

同じ明るさの画像は同じ区分に入れるため、画像数が完全に等しくなるとは限らない。境界が重複する、または空の区分ができる場合は停止する。また、各層化カテゴリの画像数がfold数に満たない場合も停止し、対象カテゴリと件数を示す。分類数を自動で減らしたり、正解ラベルだけの層化へ変更したりはしない。

特徴抽出・クラスタリング・明るさの境界計算は、fold割当前の学習画像全体を対象とする。提出用テスト画像はこれらの計算に使用しない。分割の実装は[stratification.py](../src/fan_classifier/stratification.py)、保存処理は[preparation.py](../src/fan_classifier/preparation.py)にある。

## 自動テスト

| 項目 | 検証内容 |
| --- | --- |
| 6種類のモデル生成 | timm 1.0.11でmetaデバイス上の生成、入力解像度、2出力の形状を確認 |
| 事前学習重みの取得経路 | ダウンロードをテスト用の処理に置き換え、6モデルの既定設定から対応するHugging Faceリポジトリの取得処理に到達することを確認 |
| 学習・検証・推論・確率平均 | 合成入力と小さなモデルで、処理の接続・checkpoint選択・画像IDの照合などを確認 |
| 正規化とcheckpoint | 6モデルの事前学習設定の解決、保存したmean/stdの利用、正規化情報がない場合のImageNet設定を確認 |
| OOFと誤り分析 | 検証foldだけの推論、全foldの網羅、画像ID・ラベルの照合、単体・確率平均の指標を合成入力で確認 |
| checkpointのメモリと保存 | GPUからCPUへの重みコピーを模擬し、連続更新でも保存後にコピーの参照が残らないことを確認。保存失敗時は直前の正常なcheckpointを保持 |
| VGG16の特徴抽出 | 合成入力を用い、事前学習重みを取得せずにVGG16のforward処理を確認。RGB変換と特徴の順序・保存もテスト |
| PCA・K-meansと明るさ分類 | 合成特徴・画像でクラスタリング、分位点、同値の扱い、不正な設定へのエラーを確認 |
| fold割当と再利用 | 各foldの層化カテゴリ構成、保存した割当の利用、seed・fold数の不一致検出を確認 |
| 実行環境 | CPU用依存とTensorFlow CPU 2.18.0を含む特徴抽出用依存を、それぞれハッシュ付きlockファイルで固定 |

テストは[tests](../tests)に収録している。合成画像と小型モデルで処理の接続を確認し、配布画像を必要としない構成にしている。

## 実験で記録する項目

比較する条件を変更する際は、次の情報と結果を一緒に記録する。

- モデル選択名と完全なtimm識別子、入力サイズ、事前学習重みの利用有無。
- seed、fold数、対象fold、学習・検証の件数。
- 特徴抽出の設定、PCA次元数、クラスタ数とseed、明るさの分類方法・分類数・境界値、各区分・各層化カテゴリ・各foldの件数。
- augmentation、epoch数、batch size、学習率、最良checkpointを選ぶ指標。
- Python・ライブラリ・CUDA・GPUの環境、実行コマンド。
- 各foldの検証指標、選択epoch、モデル単位の集約方法。

画像名・ラベル・予測値を含む実行成果物はローカルで管理する。結果を公開する際は、実行条件と検証範囲を併記し、配布データや秘密情報を含まない集計値を使用する。
