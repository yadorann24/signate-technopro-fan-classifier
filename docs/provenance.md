# 実装範囲と利用技術

このプロジェクトは、人物が扇子を持つかを判定する画像分類を題材に、データの分割、複数モデルの学習、推論結果の集約を共通の手順で実行できるようにしたものです。課題へのアプローチは[解法の説明](solution.md)、各ファイルの役割は[コード構成](inventory.md)、実行方法は[README](../README.md)にまとめています。

## プロジェクトで実装した部分

| 実装 | 目的 |
| --- | --- |
| モデルのregistryとfactory | 6種類のEVA/EVA02の識別子・入力サイズ・学習設定を管理し、モデル名から作成する |
| モデル別の正規化 | 事前学習設定のmean/stdを解決し、設定・checkpointへ保存して推論でも同じ値を使う |
| アスペクト比を保つリサイズと黒いパディング | 人物や扇子の形を保ち、モデルごとの入力サイズへ統一する |
| 正解ラベル・画像クラスタ・明るさによるTriple Stratified分割 | ラベルと撮影条件の偏りを考慮して学習画像をfoldに分ける |
| 分割設定とfold割当の保存・検証 | 準備時のseed・fold数と学習時の設定を一致させる |
| 学習・検証・推論の共通処理 | モデルごとの複製コードを減らし、設定とcheckpointの対応を記録する |
| 画像IDを照合する確率平均 | fold間・モデル間で予測を集約するときの重複や欠損を検出する |
| OOF予測と評価 | 各画像を学習に使っていないfoldの最良checkpointで推論し、単体・平均の指標や誤分類を比較する |
| 合成データによるテスト | 配布データを含めず、入力検証・分割・学習と推論の接続を確認する |

画像クラスタはVGG16特徴量をPCAで圧縮し、K-meansで分類して作ります。撮影場所の正解ラベルを推定する分類器ではなく、画像の見た目が近い集団を分割に利用する設計です。

明るさは学習画像の画素値から求め、指定した区分数に画像数がほぼ均等に分かれるよう、分位点を境界にします。既定は3区分で、区分数と境界値は変更できます。同じ明るさの画像は同じ区分に保つため、厳密な同数は保証しません。テスト画像は境界の計算やクラスタリングに使用せず、学習済みモデルでの推論に使用します。

## 利用するモデルとライブラリ

| 技術 | このプロジェクトでの利用 |
| --- | --- |
| timmのEVA/EVA02 | 画像分類モデルの構築と事前学習重みの取得 |
| KerasのVGG16 | 学習画像の特徴抽出 |
| scikit-learn | PCA、K-means、StratifiedKFold |
| PyTorch | 分類モデルの学習・検証・推論、checkpointの保存 |
| Albumentations、OpenCV | 画像の読み込み、変換、データ拡張 |
| NumPy | 特徴量・明るさ・予測確率の数値処理 |

EVA/EVA02やVGG16のアーキテクチャ、事前学習重み、PCAやK-meansなどのアルゴリズムは既存の技術を利用しています。このプロジェクトでの実装範囲は、それらを課題に合わせて組み合わせ、実行条件を管理し、処理間の整合性を検証する部分です。使用するバージョンは[pyproject.toml](../pyproject.toml)とlockファイルに記載しています。

## 参考にした実装と開発支援

画像分類の学習ループ、AMP（混合精度演算）、データ拡張の参考実装として、KaggleのCassava Leaf Disease Classificationに関連する `khyeh0719` の `Pytorch Efficientnet Baseline [Train] AMP+Aug` と `Pytorch Efficientnet Baseline [Inference] TTA` を挙げます。このリポジトリの推論はfold・モデル間の確率平均を行い、TTA（推論時の画像拡張）は採用していません。他コンペのデータ・学習済み重み・予測成果物は含めていません。

コードの整理、実装、テスト、文書作成にはAIコーディング支援を利用しています。

ライブラリ・モデル・事前学習重みには、それぞれのライセンスと利用条件が適用されます。データは利用権限のあるものを用意し、SIGNATE配布データやその加工物・学習成果物は再配布しないでください。
